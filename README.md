# Погода в горах и на море — pogoda-pro.ru

**Постоянный адрес:** https://pogoda-pro.ru
(зеркало GitHub Pages: https://happymanalexey-coder.github.io/kp-weather/)

Telegram Mini App (бот @broKimibot), работает и как обычный сайт.
Консенсус-прогноз из 5 источников по 52 точкам: Красная Поляна, Сочи,
Абхазия, Адыгея, Кавказский заповедник, Бали. Клик по точке → погода
сейчас, волны (для морских точек), микро-анализ, прогноз на 5 дней,
каждый день раскрывается в почасовой прогноз.

---

## 1. Архитектура

Чистая статика, **ноль зависимостей, ноль сборки, ноль бэкенда**:

```
index.html      — каркас (шапка SVG, экраны, модалка «Предложить точку»)
styles.css      — тёмная/светлая темы, весь дизайн
app.js          — UI: роутинг (#point/id, #library), библиотека, донат, PWA-регистрация
weather.js      — движок: 5 источников → консенсус → кэш localStorage 30 мин
data/points.json  — библиотека точек (52 шт., verified=true/false)
data/pending.json — очередь модерации предложенных точек (НЕ публикуется)
data/intake_state.json — offset Telegram getUpdates для intake-скрипта
manifest.json, sw.js, icons/ — PWA (установка на рабочий стол)
tools/intake_points.py — приём точек из бота (GitHub Actions, раз в сутки)
tools/gen_icons.py — генератор иконок (чистый Python + zlib)
server.py + web/ — dev-зеркало для локальной разработки (python3 server.py → :7100)
```

**Источники данных** (все открыты по CORS, без ключей):

| Источник | Что даёт |
|---|---|
| Open-Meteo best_match | текущая погода, почасовой и дневной прогноз, иконки WMO |
| Open-Meteo models | ECMWF IFS 0.25°, GFS, ICON-EU — почасовой/дневной консенсус |
| Open-Meteo Ensemble (ICON, 51 член) | честный разброс min/max по сценариям |
| MET Norway | независимый источник (Норвегия), входит в консенсус |
| Open-Meteo Marine | волны: высота, период, направление (только море/побережье) |

Как считается: почасовой консенсус = среднее всех источников в каждом часе;
дневная сумма осадков = сумме показываемых часов (числа всегда сходятся);
«разброс» = min–max по моделям + членам ансамбля. Волны показываются только
там, где Marine API вернул данные (в горах — null, блока нет).

## 2. Развёртывание с нуля

1. Форкни/склонируй репозиторий, включи GitHub Pages: Settings → Pages →
   Source = Deploy from a branch → main / (root).
2. Домен: Settings → Pages → Custom domain = `pogoda-pro.ru` (файл `CNAME`
   уже в корне). У регистратора (reg.ru): 4 A-записи на
   185.199.108.153 / .109.153 / .110.153 / .111.153 и CNAME `www` →
   `happymanalexey-coder.github.io`. SSL выпустится сам, затем включить
   Enforce HTTPS.
3. Деплой обновлений: `git push` в `main` — сайт обновится за ~1 минуту.

## 3. Бэкапы и план Б

- **Бэкап = `git clone`.** Весь проект (код, точки, очередь модерации) —
  это репозиторий. Клонируй периодически на любой диск.
- **План Б:** папка со статикой (`index.html`, `*.css`, `*.js`, `data/`,
  `icons/`, `manifest.json`, `sw.js`, `CNAME`) разворачивается на ЛЮБОМ
  статик-хостинге (Netlify, Vercel, Timeweb, reg.ru hosting) простым
  копированием — приложение не требует сервера.

## 5. Приём точек из бота (GitHub Actions)

- Раз в сутки (06:17 МСК) workflow `.github/workflows/points-intake.yml`
  читает `getUpdates` бота, парсит «Точка: Название — lat, lon», валидирует
  (те же правила, что форма в приложении: длина, алфавит, фильтр мата,
  диапазоны, не 0,0, дубликаты) и складывает в `data/pending.json`.
  **Само ничего не публикует.**
- Настройка токена: @BotFather → /mybots → выбрать бота → API Token →
  GitHub repo → Settings → Secrets and variables → Actions → New repository
  secret → имя `BOT_TOKEN`.
- Одобрение точки: перенести запись из `data/pending.json` в
  `data/points.json` (добавить `id` латиницей, `ele` — высоту,
  `region`, `verified: false`, `submitted_by` — сохранить из записи,
  тогда точка появится у автора во вкладке «Мои»), удалить из pending,
  закоммитить.

## 7. Локальная разработка

```bash
python3 server.py   # http://localhost:7100/ (dev-зеркало с дисковым кэшем)
```

Продакшн — корень репозитория; `web/` — зеркало для dev-сервера.
После правок корня синхронизировать `web/` (пути с `/`, данные через /api).

Состояние клиента — localStorage: `kp_theme`, `kp_home_ids`,
`kp_home_custom`, `kp_recent`, `kp_donate`, `kp_launches`, `kp_suggest_ts`,
`kp_suggested`, кэш погоды `wx7_*`.
