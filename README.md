# Погода в горах, на море и дома — pogoda-pro.ru

**Постоянный адрес:** https://pogoda-pro.ru
(зеркало GitHub Pages: https://happymanalexey-coder.github.io/kp-weather/)

Telegram Mini App (бот @Pagoda_assistant_bot), работает и как обычный сайт.
Консенсус-прогноз из пяти метеоисточников по 52 точкам: Красная Поляна,
Сочи, Абхазия, Адыгея, Кавказский заповедник, Бали. Клик по точке →
погода сейчас, волны (морские точки), прогноз на 5 дней с почасовой
раскладкой. **Время везде местное — для каждой точки своё** (Бали живёт
по UTC+8, Красная Поляна по UTC+3).

---

## 1. Архитектура

Чистая статика, **ноль зависимостей, ноль сборки, ноль бэкенда**:

```
index.html      — каркас (шапка SVG, экраны, «О проекте», форма точки)
styles.css      — тёмная/светлая темы, весь дизайн
app.js          — UI: роутинг (#point/id, #library, #about), библиотека,
                  свайп-назад, донат, заготовка уведомлений
weather.js      — движок: 5 источников → консенсус → кэш localStorage 30 мин
data/points.json  — библиотека точек (52 шт., verified=true/false)
data/pending.json — очередь модерации предложенных точек (НЕ публикуется)
manifest.json, sw.js, icons/ — PWA (установка на рабочий стол)
tools/gen_icons.py — генератор иконок (чистый Python + zlib)
server.py + web/ — dev-зеркало для локальной разработки (python3 server.py → :7100)
```

**Источники данных** (все открыты по CORS, без ключей):

| Источник | Что даёт |
|---|---|
| Open-Meteo best_match | текущая погода, почасовой и дневной прогноз, иконки WMO |
| Open-Meteo models | ECMWF IFS 0.25°, GFS, ICON-EU — почасовой/дневной консенсус |
| Open-Meteo Ensemble (ICON, 51 член) | честный разброс min/max по сценариям |
| MET Norway | независимый источник (Норвегия), входит в консенсус |
| Open-Meteo Marine | волны: высота, период, направление (только море/побережье) |

Как считается: почасовой консенсус = среднее всех источников в каждом часе;
дневная сумма осадков = сумме показываемых часов; «разброс» = min–max по
моделям + членам ансамбля. Часовой пояс — `timezone=auto` у всех API,
сдвиг берём из `utc_offset_seconds` ответа (запасной — оценка по долготе);
«сегодня/завтра» — по местной полуночи точки.

## 2. Развёртывание с нуля

1. Форкни/склонируй репозиторий, включи GitHub Pages: Settings → Pages →
   Source = Deploy from a branch → main / (root).
2. Домен: Settings → Pages → Custom domain = `pogoda-pro.ru` (файл `CNAME`
   уже в корне). У регистратора (reg.ru): 4 A-записи на
   185.199.108.153 / .109.153 / .110.153 / .111.153 и CNAME `www` →
   `happymanalexey-coder.github.io`. SSL выпустится сам, затем включить
   Enforce HTTPS.
3. Деплой обновлений: `git push` в `main` — сайт обновится за ~1 минуту.

## 4.1. Шеринг и deep links (этап 3)

- **Сайт:** `https://pogoda-pro.ru/point/<id>` — статическая страница
  `point/<id>/index.html` с OG-тегами (`og:title` «Погода на {название}:
  консенсус {X}°, разброс {Y}°», `og:description`, `og:image`) и редиректом
  на `/#point/<id>`. Генератор: `node tools/gen_point_pages.mjs`
  (консенсус считает боевой `weather.js`); ежедневная регенерация —
  `.github/workflows/og-refresh.yml`. Обложка: `python3 tools/gen_og.py` →
  `icons/og-cover.png`.
- **Mini-app:** `startapp=point_<id>` открывает точку; комбинации через `__`:
  `point_<id>__src_vk__skin_bali` (старые `src_`/`skin_` работают как раньше).
- **Кнопка «Поделиться»** на экране точки: сайт — Web Share API с фолбэком
  на копирование ссылки, mini-app — `t.me/share/url`. Событие `share_click`.

## 4.2. Отложенное (этап 3, НЕ реализовано — только флаги и заготовки)

## 5. Приём точек

Точки принимает ассистент **@Pagoda_assistant_bot** — мгновенно, 24/7.
Пользователь присылает боту «Название — lat, lon» (или пользуется формой
«Предложить точку» в приложении: текст копируется и открывается чат бота).
Модерация: перенести точку в `data/points.json` (добавить `id`, `ele`,
`region`, `verified: false`, сохранить `submitted_by` — точка появится
у автора во вкладке «Мои»).

## 6. Уведомления об отклонении прогноза — план (заготовка уже в коде)

Сейчас (только локально, без рассылки): подписки «точка + дата» лежат в
`kp_watch`, снимки прогнозов — в `kp_watch_snap`. При каждом открытии
точки `checkWatchedPoint()` сравнивает свежий прогноз со снимком через
`diffForecast()`: дождь появился (было <1 мм, стало ≥1 мм), ветер вырос
за порог 10 м/с, температура вышла за прежний разброс ±2°. Результат —
только в консоль, UI и рассылки нет.

Как заработает с сервером 24/7: тот же `diffForecast` переносится на
сервер, cron каждые 30–60 минут обновляет прогнозы по подпискам, при
изменениях — sendMessage через BOT_TOKEN. Клиентская часть (хранение
подписок) уже готова.

```bash

```

Продакшн — корень репозитория; `web/` — зеркало для dev-сервера.
После правок корня синхронизировать `web/`.

Состояние клиента — localStorage: `kp_theme`, `kp_home_ids`,
`kp_home_custom`, `kp_recent`, `kp_launches`, `kp_suggest_ts`,
`kp_suggested`, `kp_watch`, `kp_watch_snap`, кэш погоды `wx8_*`.
