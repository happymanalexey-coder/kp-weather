# Погода в горах и на море — Красная Поляна · Сочи · Абхазия

**Постоянный адрес (GitHub Pages, работает 24/7):**
**https://happymanalexey-coder.github.io/kp-weather/**

Telegram Mini App (работает и как обычный сайт): сводка погоды по 32 горным,
морским и прибрежным точкам — Красная Поляна, Сочи, Абхазия, Адыгея,
Кавказский заповедник. Клик по точке → погода сейчас (ветер, осадки,
облачность), микро-анализ на сегодня и завтра, прогноз на 5 дней (каждый
день раскрывается в прогноз по часам), ссылки на Windy, Yr.no и
Mountain-Forecast. «5 источников. Одна сводка.»

## Как устроено

- **Статичная версия (продакшн)** — файлы в корне репозитория:
  `index.html`, `styles.css`, `app.js`, `weather.js`, `data/points.json`.
  Браузер сам ходит в Open-Meteo и MET Norway (оба API открыты по CORS),
  агрегация и анализ считаются в `weather.js`, кэш — localStorage 30 мин.
  Хостинг — GitHub Pages из ветки `main` (корень). Деплой обновлений:
  `git push` в `main` — сайт обновится сам через ~1 минуту.
- **Серверная версия (для разработки)** — `server.py` + `web/`: та же
  логика на Python, локальный кэш на диске. Запуск: `python3 server.py`
  → http://localhost:7100/.

## Быстрый старт

```bash
cd krasnaya-polyana-weather
python3 server.py            # или: npm run dev
# открыть http://localhost:7100/
```

Python 3.10+, сторонних зависимостей нет — только стандартная библиотека.
Порт можно переопределить: `python3 server.py --port 8080`.

## Экран точки

- Sticky-шапка: «← Все точки» + название точки.
- Подзаголовок: регион · координаты · высота (высоты — из Open-Meteo
  Elevation API по точным координатам).
- «Погода сейчас · обновлено HH:MM МСК»: ветер (диапазон min–max по
  источникам), осадки, облачность.
- Кнопки внешних сервисов: Windy (карта в точке), Yr.no (поиск по
  координатам), Mountain-Forecast (ближайшая вершина их базы — маппинг
  в `app.js`, данные в `data/mf_peaks.json`).
- «Микро-анализ сегодня ▾» — сворачиваемый блок: сводка на сегодня,
  на завтра и тренд на 5 дней.
- 5 дней с почасовым раскрытием каждого дня.
- Донат-панель (0/10/20/30/50/100 ₽ или своя сумма, состояние —
  в localStorage) и на главной — панель «Вступить в комьюнити».
  Адреса задаются константами `SITE_URL`, `DONATE_URL`, `COMMUNITY_URL`
  вверху `app.js` (пока плейсхолдеры — подставить реальные ссылки).

## Подключение к Telegram-боту (@broKimibot)

Приложение готово к работе как Mini App: SDK Telegram подключается
асинхронно, страница адаптирована под мобильный экран.

1. Постоянный HTTPS-адрес уже есть: GitHub Pages (см. выше).
2. Откройте @BotFather → `/mybots` → выберите @broKimibot →
   **Bot Settings → Menu Button → Configure/Edit menu button URL** →
   вставьте адрес → задайте текст кнопки, например «Погода в горах».
3. Откройте @broKimibot в Telegram — внизу появится кнопка меню с приложением.

Токен бота хранится в `.env` (`TELEGRAM_BOT_TOKEN`, файл в `.gitignore`,
права 600). Для Mini App токен не нужен — он понадобится для уведомлений.

## Источники данных

| Источник | Что даёт | Ключ |
|---|---|---|
| Open-Meteo (best_match) | текущая погода, почасовой и дневной прогноз | не нужен |
| Open-Meteo (ECMWF IFS) | независимая модель | не нужен |
| Open-Meteo (GFS) | независимая модель | не нужен |
| Open-Meteo (ICON-EU) | независимая модель | не нужен |
| MET Norway (Locationforecast) | пятый независимый источник (высота передаётся целым числом) | не нужен |

Все пять — без ключей и бесплатно. Ответы агрегируются: среднее по
источникам + разброс (min–max). Если источник не ответил — сводка
собирается по оставшимся.

В `.env` заложены переменные `VISUAL_CROSSING_KEY`, `WEATHERAPI_KEY`,
`OPENWEATHERMAP_KEY` — зарезервированы под платные источники, в коде
не используются.

## Кэш

- Статичная версия: localStorage, ключ `wx3_*`, TTL 30 минут.
- Серверная версия: `cache/{id}.json`, TTL 30 минут (`CACHE_TTL_MIN` в `.env`).

## Вердикты (в блоке 5 дней)

- 🔴 **Не стоит**: гроза, осадки ≥ 8 мм/сутки или ветер ≥ 15 м/с.
- 🟡 **Осторожно**: осадки ≥ 2 мм, ветер ≥ 8 м/с или облачность ≥ 90 %.
- 🟢 **Отлично**: всё остальное.

Микро-анализ: окна осадков по часам, лучшее окно для выхода, ветер, туман,
гроза — на сегодня и на завтра.

## Структура

```
index.html, styles.css, app.js, weather.js — продакшн (статика, GitHub Pages)
server.py          — бэкенд для разработки (stdlib): статика + /api/*, кэш
web/               — серверная версия фронта
data/points.json   — 32 точки: id, имя, координаты, высота (int), регион
data/mf_peaks.json — база вершин Mountain-Forecast в регионе (для маппинга)
docs/              — отчёт по координатам и источникам (шаг 1)
share.sh           — сервер + временный публичный туннель Pinggy
```

## Как обновить точки

Правите `data/points.json` (id, name, lat, lon, ele, region) — и делаете
`git push`; статичная версия подхватит файл сама. Высоты — целые числа
(требование MET Norway API).

## Осознанные отклонения от ТЗ

- **React/Vite → vanilla JS без сборки.** Надёжнее для MVP: ноль зависимостей,
  работает где угодно. Миграция на React возможна позже без изменения API.
- **Yr.no** — ссылка ведёт на поиск по координатам: у Yr нет страниц
  прогноза по произвольным lat/lon.
- **Mountain-Forecast** — ссылки name-based (так устроен их сайт), точка
  привязана к ближайшей вершине их базы: в регионе есть только
  Mount-Fisht, Oshten и Mount-Agepsta.
- **Windy** — используется query-формат `?lat,lon,zoom`: path-формат их
  SPA игнорирует и показывает дефолтную локацию.
- **Уведомления отложены** (по решению владельца). План: бот шлёт сводку
  за сутки до похода (нужен polling getUpdates или webhook + chat_id).
- **Платные источники (Visual Crossing, WeatherAPI, OWM)** не подключены —
  пять бесключевых источников уже дают разброс моделей.
